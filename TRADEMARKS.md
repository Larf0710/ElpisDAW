# ElpisDAW Trademark Policy

Status: **PRE-PUBLIC POLICY — EFFECTIVE WHEN PUBLISHED BY THE ELPISDAW PROJECT**

## Purpose

The ElpisDAW source license governs use of the source code. It does not grant
rights to use the ElpisDAW name, official logos, visual identity, or official
project labels. This policy explains which uses of those project identifiers
are allowed and which require written permission.

This policy does not state that any project identifier is registered in a
particular jurisdiction. It preserves any rights that apply under relevant law.

## Project Marks

For this policy, **Project Marks** means:

- the `ElpisDAW` name and distinctive spelling;
- official ElpisDAW logos, icons, and visual identity assets; and
- the labels `Official ElpisDAW Provider`, `ElpisDAW Official Provider`,
  `Verified ElpisDAW Extension`, and confusingly similar official-status labels.

Names and marks belonging to model authors, Provider projects, dependencies,
and other third parties are controlled by their respective owners. This policy
does not grant rights to those marks.

## Uses That Do Not Require Separate Permission

You may use the ElpisDAW word name, without an official logo, to:

- truthfully refer to the ElpisDAW project or an unmodified official release;
- link to an official ElpisDAW project page or release location;
- accurately describe compatibility with ElpisDAW; or
- state that an independent project is based on ElpisDAW source code.

Referential use must not imply sponsorship, endorsement, verification, or
official project status. An independent project that states it is based on
ElpisDAW must use a distinct product name and branding and display an equally
prominent statement that it is independent and is not endorsed by the ElpisDAW
project.

You may redistribute an unmodified official ElpisDAW release obtained from an
official project location if you preserve its name, version information,
notices, signatures, and package contents and do not imply that you produced or
verified the release.

## Uses That Require Prior Written Permission

Written permission is required before you:

- distribute a modified build under the ElpisDAW name or official branding;
- use a Project Mark as part of a product, service, company, organization,
  package, application-store listing, domain name, account name, or event name;
- use an official ElpisDAW logo or a confusingly similar design outside
  truthful reference to an official project page or unmodified official release;
- sell merchandise or run advertising, sponsorship, fundraising, or promotional
  activity using a Project Mark; or
- claim that a Provider, Extension, fork, build, service, or person is official,
  verified, certified, sponsored, or endorsed by the ElpisDAW project.

Permission for one use does not authorize another use. Written permission may
set conditions for quality, security updates, presentation, duration, or
withdrawal.

## Forks and Modified Distributions

Forks and modified distributions must use their own name, logo, versioning, and
release channel. They may make a truthful text statement such as "based on
ElpisDAW" when the independent status statement required above appears with it.
They must not remove third-party notices or describe modified binaries as an
official ElpisDAW release.

The MPL-2.0 obligations for covered source files continue to apply independently
of this policy.

## Permission Requests and Misuse Reports

No public trademark-permission or misuse-reporting channel is open during the
pre-public stage. Until the project publishes an approved contact method, uses
that require written permission remain unauthorized and cannot be approved by
silence, prior discussion, or issue comments.

When a contact method is published, requests should identify the requester, the
exact Project Mark, the proposed use, the distribution channel, and the intended
duration. Do not send credentials, private project files, model weights, or
unrelated personal data.

## No Waiver

A failure to object to a particular use does not waive this policy or any rights
in the Project Marks. The project may update this policy by publishing a revised
version; a written permission already granted remains subject to its own terms.
